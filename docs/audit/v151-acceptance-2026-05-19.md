# mcp-servicetitan v1.5.1 — Acceptance Audit (2026-05-19)

## Headline

ST-77 alignment + payroll-debt hardening. 86 tools (was 86 on v1.5.0 — the new `jobs_hold_reasons_list` was already counted because Phase 4b shipped with the v1.5.1 commit set). 453 tests passing (up from 437 on v1.5.0).

## What shipped

### ST-77 visible additions (Phase 4)
- **`st_list_appointments`** now accepts `active?: boolean` filter and surfaces the field in responses (ST-77 GET addition).
- **`jobs_hold_reasons_list`** — new tool wrapping `GET /jpm/v2/tenant/{tid}/jobs/hold-reasons`.
- **`isAutoDispatched`** plumbed end-to-end:
  - `get_job` + `st_list_jobs` now return the field (ST-77 schema addition; passthrough only — no extra fetch).
  - `dispatch_override_audit` composite accepts `includeAutoDispatchedFlag: true` to batch-fetch parent jobs and annotate each override row.
  - taylor-ai `gate-st.js` mapper writes `is_auto_dispatched` to D1; migration `migrations/0023_jobs_is_auto_dispatched.sql` adds the column + index.

### Foundational debt cleanup (Phase 1–3, 5)
- **`readST()` / `readSTPaged()`** in `src/st.ts` — single live-ST entry point. ~25 call sites migrated. Remaining `env.ST_PROXY.fetch` sites are legitimate non-GET (escape hatch, POSTs, durable-write status).
- **Filter-preservation test harness** at `src/tools/__tests__/filter_preservation_helper.ts` — generalizes the `unsupportedLiveFilters()` regression pattern. Applied to payroll list tools.
- **stEndpoint coverage gate**:
  - `GET /admin/endpoints/coverage` returns 200 when every non-exempt tool declares an `stEndpoint`, 422 otherwise.
  - `src/tools/__tests__/coverage_gate.test.ts` enforces the same invariant in vitest so preflight catches new tools that ship without a descriptor.
  - Backfilled descriptors on 13 previously-undeclared tools (writes, composites, search_pricebook_all).
  - 3 Siro tools exempted (external API, no ST endpoint).

## Risk + rollback

Additive everywhere. The D1 column defaults to 0 and ST_SYNC fills it on the next 2-hour tick. Rollback = revert the mcp-servicetitan merge commit + redeploy v1.5.0. The D1 column stays in place even on rollback (it costs nothing and ST_SYNC will keep populating it on whatever worker version is live).
