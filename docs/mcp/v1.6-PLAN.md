## v1.6 scope (canonical list, re-scoped to reality)

### 1. Finish the `readST` sweep — SMALL (was billed as the big item)
Migrate the 3-4 remaining hand-rolled **read** tools (`get_capacity`, `st_get_capacity_slots`, `search_pricebook_all`, audit `st_run_report`) onto `readST`/`readSTPaged`. Leave `st_call` + write tools alone. **Effort: ~half a day.** Risk: low (mechanical, each tool already has tests).

### 2. Response-shaper rollout — MEDIUM (the actual bulk item)
Only 24 of ~86 tools declare `transformResult`. Roll the envelope-stripping/array-cap shaper out to the remaining hand-rolled tools where it adds value (skip tiny single-object reads where there's no envelope noise). **Effort: 1-2 days.** Risk: low-medium — must not change semantic payloads callers (Retell, Pulitzer, Claude Code) depend on; add a snapshot test per tool touched.

### 3. Filter-preservation coverage — MEDIUM, incremental
Adopt the v1.5.1 `assertFilterPreservation` harness across the ~80 tools (one test per tool). Locks out the silent-filter-drop bug class that bit `payroll_job_timesheets_list`. **Effort: spread — can land tool-by-tool.** Risk: very low (test-only).

### 4. `pricebook_health_check_materials_equipment` — BLOCKED
New composite mirroring `pricebook_health_check_services` for materials + equipment. **Prerequisite:** upstream taylor-ai nightly sync of `pb_materials` + `pb_equipment` to D1. Those tables exist and sync (per qsc-infra protected-modules) — **verify freshness before building.** If sync is current, this unblocks. **Effort: ~1 day once unblocked.**

### 5. ST-77.2/77.3 product probes — RESEARCH, separable
Each is an independent investigation, not guaranteed to yield a tool:
- Equipment auto-attach
- Dispatch Pro multi-appointment
- FTK dispatch links
- Contact Center Pro
- Inventory landed costs

Recommend: spike each as a throwaway `st_call` probe first, promote to a tool only if there's a real read surface + a caller who wants it. **Don't commit to all five for v1.6** — pick the 1-2 with a known consumer.

### 6. Tool-pack splitting — ARCHITECTURE, biggest design lift
Segment ~86 tools into role/domain views (default / payroll / dispatch / accounting / pricebook / admin) to relieve context pressure on MCP clients. The `lockdown` role from v1.5.2 is the proof-of-concept that `toolsForRole` can gate by more than admin/default. **Effort: 2-3 days + design.** Risk: medium — changes the tool-discovery contract; needs a plan-mode design pass and Luke sign-off before code. **Candidate to defer to v1.7** if v1.6 should stay sharp.
